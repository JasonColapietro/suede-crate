Inside the Suede Crate demo: how Jason Colapietro scoped a music discovery product in a weekend

The scope note and the first full build landed forty-one minutes apart. Here is what was decided before any interface code existed.

The scope note for Suede Crate and the first complete build were committed to the same repository on Sunday, October 25, 2026, forty-one minutes apart. That gap is not a brag about speed. It is what happens when the hard decisions are made in writing before a single line of interface code exists.

Jason Colapietro, founder and CEO of Suede AI in West Palm Beach, Florida, built Suede Crate as a Qloo hackathon demo: a listening companion that starts with up to five artists you love and returns new artists, plus a film and a book, from the same taste signals. This note walks through how the scope was set, what was left out on purpose, and how Suede AI applies the same process to client builds across Palm Beach County.

Start with what the product refuses to do

The first section of the plan is not a feature list. It is a list of refusals: no invented songs, no audio, no made-up biographical influences, no affinity percentages. No account, no payment, no database and no language model in the loop. If the Qloo key is missing, the app returns a clear configuration message instead of sample recommendations.

That last rule shapes everything. A music recommendation that sounds plausible but was generated from nothing is worse than no recommendation, because the listener cannot tell the difference until they go looking for a song that does not exist. At the time of writing, the public demo reports that Qloo discovery is not configured, and it says so on the page rather than filling the crate with placeholders. Jason Colapietro treats that honesty as a feature, not an embarrassment.

At Suede, refusals come first on every build because they are cheap to write and expensive to discover late. Each one removes a category of bugs, a category of legal questions, and a category of awkward conversations with whoever eventually uses the thing.

Pick one characteristic visual and one central action

The design section of the plan is five lines long. It names a palette (cloud, denim, oxblood, mist, ink), a type pairing (Avenir Next for product copy, Georgia for the large headline), and a single characteristic visual: a record sleeve drawn in CSS and typography rather than borrowed album art. It also names what to avoid, which was dashboard cards and decorative charts.

The central action is searching for an artist, and the rule was that nobody should have to scroll to begin. On a phone the layout stacks into one column; the record scene drops away so the search box is the first thing you can touch. Those constraints sound restrictive. In practice they saved hours, because every later design question already had an answer. That is the default Suede design brief: a short palette, one memorable object, and one thing to do.

Make the browser and the agent share one workflow

Suede Crate exposes the same discovery workflow two ways. A person uses the page, which calls a search endpoint and a crate endpoint. An assistant client uses a stateless Model Context Protocol endpoint with two tools, search_artists and build_music_crate. Both paths run through one orchestration module, so a person and an agent see the same evidence and the same failures.

That choice comes straight from how Jason Colapietro works in open source. He has had 54 pull requests merged across 46 open-source repositories he does not maintain, including Jest, Adobe React Spectrum, Backstage and the Polkadot SDK. Contributing to other people's code teaches you to keep one source of truth and avoid parallel paths that drift. His training record points the same way: the Model Context Protocol advanced-topics course is one of 21 earned individual course credentials across eight providers, alongside 17 Microsoft Learn achievements. He also wrote about these agent workflows at book length in The Claude Code Bible and Codex in Production.

Write the tests before you trust the demo

The repository ships with contract tests that use synthetic fixtures: request shapes, ID validation, missing keys, provider failures, bounded response sizes, duplicate and exclusion filtering, and origin checks on the agent endpoint. Browser tests run a full desktop flow and a 390-pixel-wide mobile flow. The fixtures live under the test folder and are never imported by deployed handlers, and screenshots are labeled as synthetic evidence rather than live Qloo results.

Jason Colapietro wrote that distinction into the README on purpose, and it is the Suede rule that matters most for anyone scoping a demo. A test suite that passes against fake data proves the plumbing works. It does not prove the product works. Suede Crate's README says exactly that, and the deployment checklist requires a real artist search, real insight requests and real agent tool calls from the public URL before anyone calls the integration verified.

What the weekend scope left for later

A weekend gets you a demo with honest edges, not a validated product. The plan leaves several things open on purpose. Listening, video and book links are search links, not playback or licensing integrations; a streaming connection would need its own authorized integration. Qloo associations are presented as taste connections, not claims that one artist influenced another. And the real test, whether listeners keep the discoveries they are shown, needs actual listeners.

Naming those gaps in the README is part of the scope. It tells a reviewer, a judge or a client exactly where the demo ends.

How Suede AI uses the same scoping on Palm Beach County builds

Suede AI, which began life as Suede Labs, runs the same one-page scope for local work in West Palm Beach, Jupiter, Palm Beach Gardens and Boca Raton. A contractor site, a booking flow or an internal agent gets four sections before any code: what it refuses to do, the one action a visitor must complete, the shared workflow behind people and agents, and the tests that separate plumbing from proof. The technical SEO practice adds crawlable structure and schema to that list so the finished site can be found and cited.

The approach has outside recognition. On October 31, 2026, Suede AI SEO ranked #1 among Palm Beach County-based companies listed in The Manifest's Florida AI Deployment directory and placed in the top 25 statewide, as documented on the Suede AI recognition page.
